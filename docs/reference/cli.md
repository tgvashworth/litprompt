# CLI commands

litprompt has three commands — `build`, `check`, and `lock` — plus a set of global flags.

## Global flags

These apply to every command:

| Flag | Description |
|---|---|
| `-v`, `--verbose` | Show files processed and imports resolved. |
| `-d`, `--debug` | Show parsing details and hash comparisons. |
| `-q`, `--quiet` | Suppress all output except errors. |
| `--mock-dir <dir>` | Use a local directory for remote content instead of the cache (for testing). |

Logs go to **stderr**; build output goes to **stdout**, so you can pipe a build cleanly.

## `build`

```
litprompt build [file.md|dir/] [flags]
```

Strips comments, resolves imports, and substitutes variables. Output goes to stdout by default.

There are three input modes:

- **Single file** — `litprompt build prompt.md`. Builds one file. Add `-o out.md` to write it somewhere.
- **Directory** — `litprompt build prompts/ -o out/`. Recursively builds every `.md` file, mirroring the tree into the output directory.
- **Config** — `litprompt build` with **no argument** reads `litprompt.yaml` (or `.yml`) from the current directory and builds every entry. See the [config reference](config.md).

You can also read from stdin: `cat prompt.md | litprompt build -`.

### Flags

| Flag | Description |
|---|---|
| `-o`, `--output <path>` | Output file or directory. Omit to print to stdout. |
| `--match <glob>` | In directory mode, filter which files to build (e.g. `'**/prompt.md'`). Uses `**` for recursive matching. |
| `--header <short\|full>` | Insert a generated-file comment after the frontmatter. |
| `--interlock <analytics\|enforce>` | Stamp an interlock line into the output. |
| `--interlock-param <name>` | Tool-parameter name used in the interlock line (default `interlock_tokens`). |
| `--interlock-manifest <path>` | Where to write the interlock manifest (default `interlocks.json`). |
| `--config <path>` | Build a named config file instead of discovering one in the cwd. Cannot be combined with a source argument. |
| `--vars <file>` | A `.env`-format file of variable values. Repeatable; later files override earlier ones on key collision. |

`--header short` inserts `<!-- litprompt src/file.md -->`; `--header full` inserts `<!-- Generated by litprompt from src/file.md. Do not edit. -->`.

In **config mode** (no argument, or `--config`), the per-build settings come from the config file, so `-o`, `--header`, and `--match` are ignored.

## `check`

```
litprompt check [file.md|dir/] [flags]
```

Validates sources **without producing output**. It verifies that:

- all imports resolve,
- the lockfile is current for remote imports,
- every variable directive resolves against the supplied `--vars` (an unset value is an error),
- there are no circular dependencies.

Errors are reported per source, and the command exits non-zero if any source fails. This is the CI-friendly counterpart to `build` — "will this build?" without writing anything.

Like `build`, it takes a single file, a directory, or (with no argument / `--config`) every source in a config.

### Flags

| Flag | Description |
|---|---|
| `--match <glob>` | In directory mode, filter which files to check. Ignored in config mode. |
| `--config <path>` | Check every source in a named config instead of discovering one in the cwd. Cannot be combined with a source argument. |
| `--vars <file>` | A `.env`-format file of variable values. Repeatable. |

## `lock`

```
litprompt lock <file.md|dir/>
```

Fetches every remote import via git (HTTPS, falling back to SSH), computes its SHA-256 hash, writes/updates `litprompt.lock`, and caches content in `~/.cache/litprompt/`. This is the **only** command that hits the network — `build` and `check` read from the cache and verify against the lockfile.

Private repos work automatically using your existing git auth (SSH keys, credential helpers, `GITHUB_TOKEN`).

See the [lockfile reference](lockfile.md) for the file format and [Import from another repo](../guides/remote-imports.md) for the workflow.
